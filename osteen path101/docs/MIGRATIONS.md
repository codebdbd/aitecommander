# Система миграций БД

В проекте используется лёгкая внутренняя система миграций для SQLite на базе `PRAGMA user_version`.
Миграции хранятся в директории `app/models/migrations/` и применяются последовательно.

- Версия схемы хранится в `PRAGMA user_version` (целое число).
- Файлы миграций именуются с префиксом из 4 цифр и подчёркиванием: `0001_*.sql|py`.
- Поддерживаются два формата:
  - `.sql` — исполняется целиком через `executescript`.
  - `.py` — модуль должен содержать функцию `migrate(conn, logger)`, где `conn` — `sqlite3.Connection`.

## Где запускаются миграции

Миграции применяются автоматически при старте приложения в `Database.initialize_or_migrate()`.
Раннер: `app/utils/db/migrations.py`, класс `MigrationRunner`.

## Добавление новой миграции

1. Создайте файл в `app/models/migrations/` с номером следующей версии, например:
   - `0005_add_table_x.sql` — для простых изменений;
   - `0005_add_table_x.py` — если нужна сложная логика/проверки/перенос данных.
2. В `.py`-миграции реализуйте функцию:
   ```python
   def migrate(conn: sqlite3.Connection, logger):
       # любые проверки/DDL/перенос данных
       conn.execute("...")
   ```
3. Запустите приложение или тесты — миграция будет применена автоматически.

## Особенности и рекомендации

- Каждая миграция должна быть идемпотентной: повторный запуск не должен ломать базу.
- Для `.sql` используйте `IF NOT EXISTS`, где это возможно.
- Для `.py` выполняйте проверки состояния (например, существование колонок/индексов) перед изменениями.
- Тяжёлые миграции выполняются под глобальной блокировкой `db_lock` — UI не должен блокироваться, запускайте в фоновых задачах.
- Если миграция падает, версия схемы не повышается. После устранения причины повторный запуск догонит схему до актуальной.

## Текущие миграции

- `0001_init.sql` — начальная схема (таблицы sphere/section/category/link/backup).
- `0002_add_link_browser_key.py` — добавляет колонку `browser_key` в `link`.
- `0003_change_link_unique.py` — пересоздаёт `link` с `UNIQUE(category_id,name,url,args)`.
- `0004_create_nocase_indexes.py` — создаёт case-insensitive уникальные индексы для `sphere/section/category`.

## Решение конфликтов из-за дубликатов

Если `0004` не может создать индексы из‑за дубликатов (по имени с разным регистром),
используйте встроенные утилиты (CLI) из `app/models/db.py`:

- Поиск дубликатов:
  ```bash
  python -m app.models.db --detect-duplicates --json
  ```
- Разрешение дубликатов (переименование или удаление):
  ```bash
  python -m app.models.db --resolve-duplicates rename --create-indexes-after
  ```

После устранения дубликатов повторный запуск приложения успешно применит оставшиеся миграции.
