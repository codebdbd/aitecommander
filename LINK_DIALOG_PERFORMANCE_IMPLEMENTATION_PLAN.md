# План ускорения диалога добавления ссылок

> **AGENT: К ИСПОЛНЕНИЮ**
>
> Статус: `IN_PROGRESS`
>
> Приоритет: высокий
>
> Исполнитель должен выполнять этапы последовательно, после каждого этапа запускать указанные тесты и не смешивать изменения с общим производственным аудитом.

## 1. Цель

Убрать задержки и подвисания в сценариях:

- открытие диалога добавления или редактирования ссылки;
- выбор сферы, раздела и категории;
- выбор установленного приложения;
- автоматическое получение имени и иконки файла, ярлыка или веб-ссылки;
- закрытие диалога во время фоновой обработки.

Первый кадр диалога должен показываться без синхронного чтения профилей браузеров, массовой загрузки иконок и цепочки дополнительных SQL-запросов.

## 2. Подтверждённые причины задержек

### P1. Иконки сфер загружаются до первого показа и повторно после него

`LinkDialog._populate_spheres()` синхронно разрешает путь и создаёт `QIcon` для каждой сферы. После `showEvent()` `_apply_sphere_icons()` повторяет обход.

Затронутые файлы:

- `app/views/windows/dialogs/link_dialog/link_dialog.py`
- `app/views/windows/dialogs/link_dialog/icon_utils.py`
- `app/utils/ui/icon/loading_service.py`

### P1. Иерархия загружается несколькими синхронными вызовами

До `dlg.exec()` последовательно запрашиваются сферы, иерархия текущей категории, разделы и категории. После первого показа разделы и категории снова запрашиваются для установки иконок.

Затронутые файлы:

- `app/controllers/ui/dialogs/link_operations_controller.py`
- `app/controllers/ui/dialogs/link_dialog_controller.py`
- `app/views/windows/dialogs/link_dialog/link_dialog.py`
- `app/views/windows/dialogs/link_dialog/handlers_mixins/hierarchy_mixin.py`

### P1. Менеджер профилей создаётся для новой Web-ссылки без необходимости

`_extract_profile_and_user_args()` вызывается и для пустой новой ссылки. Первый вызов создаёт менеджер браузеров и синхронно читает persistent cache. При редактировании ссылки с аргументом профиля возможен синхронный обход папок браузера и чтение `Preferences`.

Затронутые файлы:

- `app/views/windows/dialogs/link_dialog/link_dialog.py`
- `app/utils/browser/browser_profiles/profile_manager.py`
- `app/utils/browser/browser_profiles/async_profile_manager.py`

### P1. Иконка выбранного приложения извлекается в UI-потоке

После закрытия `InstalledAppsDialog` метод `cache_app_icon()` синхронно вызывает Shell/COM, извлекает ресурс из EXE/DLL и записывает PNG.

Затронутые файлы:

- `app/views/windows/dialogs/link_dialog/handlers_mixins/apps_picker_mixin.py`
- `app/utils/system/installed_apps_service.py`

### P2. Список приложений целиком строится в UI-потоке

Получение приложений выполняется в фоне, но `_on_apps_loaded()` одним циклом создаёт все `QListWidgetItem`. Иконки приходят отдельным сигналом для каждой строки, что создаёт длинную очередь UI-событий.

Затронутый файл:

- `app/views/windows/dialogs/installed_apps_dialog.py`

### P2. Ярлык `.lnk` предварительно парсится в UI-потоке

После выбора файла через `QFileDialog` выполняется синхронный `parse_lnk()`, хотя полная обработка пути уже имеет фоновый механизм.

Затронутый файл:

- `app/views/windows/dialogs/link_dialog/handlers_mixins/file_dialog_mixin.py`

### P2. Отмена задачи не останавливает уже начатую блокирующую операцию

`TaskHandle.cancel()` подавляет результат, но не прерывает выполняемый callable. `cancel_event` помогает между фазами, однако текущий HTTP/COM-вызов продолжает занимать поток до завершения или таймаута.

Затронутые файлы:

- `app/views/windows/dialogs/link_dialog/handlers_mixins/link_processing_mixin.py`
- `app/utils/links/parser/fetcher.py`
- `app/utils/links/parser/http_client.py`

## 3. План реализации

### Этап 1. Сделать открытие диалога лёгким

Статус этапа: `COMPLETED`

- [x] Изменить `_populate_spheres()`: добавлять только текст и ID, без разрешения и загрузки иконок.
- [x] Оставить единственный отложенный проход установки иконок после первого кадра.
- [x] Выполнять дисковую загрузку небольшими порциями через очередь событий, чтобы не блокировать интерфейс длинным циклом.
- [x] Не запрашивать разделы и категории повторно ради иконок. Сохранять полученные записи в состоянии диалога и применять иконки к уже имеющимся данным.
- [x] Удалить повторный вызов `_load_rotation_state()` из `_load_initial()`.
- [x] Убрать `ensure_user_icons_dir()` из конструктора; каталог создаётся непосредственно перед записью иконки.

Критерии готовности:

- до `showEvent()` не создаётся ни одна иконка сферы, раздела или категории;
- каждая коллекция иерархии запрашивается не более одного раза при открытии;
- выбранные sphere/section/category после открытия полностью совпадают с прежним поведением;
- отсутствие или повреждение иконки не задерживает и не закрывает диалог.

### Этап 2. Собрать единый снапшот иерархии

- [ ] Убрать дублирование между `LinkOperationsController` и `LinkDialogController` при подготовке данных.
- [ ] Определить один API `get_initialization_data()`, возвращающий сферы, выбранную иерархию, разделы выбранной сферы и категории выбранного раздела.
- [ ] Сначала использовать готовый кэш `StructureBusinessLogic`; SQL fallback выполнять в контроллере, а не во view/mixin.
- [ ] Отличать пустой валидный кэш от отсутствующего кэша. Проверка `if cached_items:` не должна превращать пустую коллекцию в повторный SQL-запрос.
- [ ] При смене сферы или раздела загружать только зависимый уровень и обновлять локальный кэш диалога.
- [ ] Не переносить модели БД или SQL-вызовы в `LinkDialog` и его mixin-классы.

Критерии готовности:

- view получает готовые DTO и не обращается напрямую к БД;
- открытие диалога не вызывает повторных запросов разделов/категорий после первого кадра;
- пустые сферы и разделы не вызывают повторный fallback-запрос;
- изменения структуры, пришедшие через сигналы, продолжают отображаться.

### Этап 3. Сделать профили браузера полностью ленивыми

- [ ] Немедленно возвращать `([], "")` для новой ссылки без `args`, не создавая `BrowserProfileManager`.
- [ ] Разбирать аргумент профиля синтаксически без сканирования профилей на диске.
- [ ] Сохранённый `browser_key` и directory использовать как лёгкий placeholder для текста кнопки.
- [ ] Получать полное имя/email профиля через `AsyncBrowserProfileManager` после показа либо только при открытии выбора профиля.
- [ ] Не менять существующую семантику одиночного профиля, rotation profiles и пользовательских аргументов.

Критерии готовности:

- открытие новой Web-ссылки не читает `browser_profiles.json`;
- открытие ссылки без профильного аргумента не сканирует каталоги браузеров;
- редактирование профильной ссылки сразу показывает диалог и позже уточняет подпись профиля;
- выбор и сохранение профилей остаются совместимыми с текущими данными.

### Этап 4. Перенести обработку выбранного приложения в фон

- [ ] После выбора приложения сразу заполнить путь, имя и аргументы.
- [ ] Запустить `cache_app_icon()` через отдельную фоновую задачу без DB-lock.
- [ ] На время обработки показывать штатную иконку типа `program`, не блокируя форму.
- [ ] Применять результат только если диалог не закрыт и выбранное приложение всё ещё актуально.
- [ ] Использовать `cached_image` из `InstalledAppsDialog`, если оно уже получено, чтобы не извлекать одну и ту же иконку второй раз.
- [ ] Добавить cooperative cancellation и уникальный generation/task ID для выбора приложения.

Критерии готовности:

- после нажатия «Выбрать» окно не зависает;
- иконка появляется автоматически без ручного обновления;
- быстрый выбор другого приложения не применяет результат предыдущего;
- закрытие диалога во время извлечения не вызывает callback к удалённым Qt-объектам.

## 6. Ограничения реализации

- Не выполнять крупный рефакторинг общей системы иконок вне затронутого сценария.
- Не создавать `QPixmap` или `QIcon` в фоновом потоке; в фоне получать путь/`QImage`, Qt-иконку создавать в GUI-потоке.
- Не выполнять HTTP, COM, обход каталогов, SQL fallback и запись файлов в GUI-потоке.
- Не менять формат сохранённых ссылок и профильных аргументов.
- Не удалять существующие механизмы кэширования; устранить дублирование и неверные cache-miss проверки.
- Не включать несвязанные изменения из `PRODUCTION_AUDIT_PLAN.md` в коммиты реализации.
