1. Назначение документа

Документ является исчерпывающим техническим заданием на проектирование, верстку, программирование, тестирование и публикацию официального сайта Aite Commander. Он должен использоваться как единый источник требований для дизайнера, frontend-разработчика, QA и лица, принимающего работу.

При конфликте между устными допущениями разработчика и данным документом приоритет имеет этот документ. При конфликте между спецификацией и более поздним явным решением владельца продукта приоритет имеет более позднее согласованное решение.

1.1. Цель сайта

За 3–5 секунд объяснить посетителю, что Aite Commander — командный центр для Windows.

Показать основную ценность: собрать сайты, файлы, папки, программы, скрипты и заметки вокруг реальных задач.

Показать вторую ценность: подготовленную структуру можно использовать не только для себя, но и передавать другому человеку.

Продемонстрировать реальные интерфейсы программы вместо абстрактных иллюстраций.

Подвести пользователя к скачиванию Aite Commander для Windows.

Создать узнаваемый визуальный образ, связанный с логотипом, а не типовой SaaS/AI-лендинг.

1.2. Что сайт не должен делать

Не позиционировать продукт как менеджер закладок.

Не сводить продукт к набору технических функций.

Не строить коммуникацию только вокруг помощи другим: сначала продукт полезен самому пользователю.

Не использовать абстрактную “AI-эстетику” ради современности.

Не превращать страницу в каталог одинаковых карточек.

Не использовать вымышленные возможности, неподтвержденные интерфейсом/продуктом.

2. Основная продуктовая идея и позиционирование

Зафиксированное позиционирование: Aite Commander — командный центр для Windows.

Основная логика коммуникации страницы: хаос и повторный поиск → порядок для себя → быстрый возврат к задаче → возможность сделать путь понятным для другого человека.

Ключевая формула продукта: ресурсы разных типов объединяются не по техническому типу, а по реальной задаче пользователя.

Важный смысловой переход: “Сначала — для себя. Потом оказывается, что созданная структура полезна и другим”.

Красный круг из логотипа переносится в дизайн как редкий микроакцент, а не как повсеместный bullet.

7. Дизайн-система

7.1. Визуальный характер

7.2. Что запрещено

Blue-purple SaaS/AI gradients как основной визуальный язык.

3D-сферы, абстрактные “AI-объекты”, стоковые люди с ноутбуками.

Perspective/rotation реального UI продукта.

Карточка на каждую мысль.

Слишком много красных кругов / повсеместное копирование логотипа.

Микротекст и чрезмерно узкие колонки.

16. Рекомендуемая техническая реализация frontend

Сайт не требует тяжёлого SPA-фреймворка. Предпочтительна статическая генерация/обычный HTML с минимальным JavaScript. Основной критерий — быстрый первый рендер, семантика, простота поддержки и отсутствие ненужной зависимости от runtime framework.

16.1. Рекомендуемый baseline

Semantic HTML5.

CSS Custom Properties для design tokens и тем.

TypeScript или современный ES2022+ JavaScript для theme/menu/FAQ enhancement.

Vite как лёгкий build tool — предпочтительно, но не обязательно.

Если выбран Astro/React/Vue/Svelte — страница должна быть prerender/static и не тянуть большой client runtime без необходимости.

18. Accessibility

Минимальная цель: WCAG 2.2 AA.

Полная клавиатурная навигация.

Видимый `:focus-visible` для ссылок, кнопок, theme selector, accordion.

Минимальная кликабельная область 44×44 px.

Контраст текста ≥ 4.5:1 для обычного текста, ≥ 3:1 для крупного.

Не передавать смысл только цветом.

Логический tab order соответствует визуальному.

Mobile menu и theme menu имеют корректные `aria-expanded`, `aria-controls`, roles по необходимости.

FAQ читабелен screen reader.

Поддержать `prefers-reduced-motion`.

Декоративные изображения исключаются из accessibility tree.

23. Безопасность и инфраструктурные заголовки

HTTPS only.

Не вставлять пользовательский HTML / eval.

Если нет внешних скриптов — использовать строгий CSP.

Рекомендуемые headers: Content-Security-Policy, Referrer-Policy, X-Content-Type-Options: nosniff, Permissions-Policy.

Внешние ссылки при `target="_blank"` получают `rel="noopener noreferrer"`; по умолчанию не открывать новую вкладку без причины.

Staging закрыть от индексации.
