# Архитектура проекта Ostein

Этот документ описывает архитектуру, структуру и ключевые компоненты проекта Ostein.

## 1. Обзор

Ostein — это настольное приложение, разработанное на Python с использованием фреймворка PyQt6 для создания графического пользовательского интерфейса. Приложение предназначено для организации и быстрого доступа к ссылкам, файлам и программам.

Архитектура приложения следует паттерну **Model-View-Controller (MVC)**, что обеспечивает четкое разделение бизнес-логики, данных и их представления.

## 2. Технологический стек

- **Язык программирования**: Python
- **Графический интерфейс**: PyQt6
- **База данных**: SQLite
- **Зависимости**: Основные зависимости перечислены в файле `requirements.txt`.

## 3. Структура проекта

```
osteen path/
├── .venv/              # Виртуальное окружение Python
├── app/                # Основной исходный код приложения
│   ├── __init__.py
│   ├── main.py         # Точка входа в приложение
│   ├── config.py       # Конфигурационные константы (пути)
│   ├── settings.py     # Настройки приложения (сохраняются в JSON)
│   ├── controllers/    # Контроллеры (логика UI)
│   ├── models/         # Модели (работа с данными)
│   └── views/          # Представления (компоненты GUI)
├── requirements.txt    # Зависимости проекта
├── setup.py            # Скрипт установки (не используется)
└── ARCHITECTURE.md     # Этот файл
```

### 3.1. Ключевые компоненты

#### `app/models`
Отвечает за работу с данными.
- **`db.py`**: Класс `Database` для инкапсуляции всех операций с базой данных SQLite. При первом запуске автоматически создает БД из `schema.sql` и наполняет ее начальными данными (сферами). Реализует CRUD-операции для всех сущностей и механизм резервного копирования.
- **`schema.sql`**: SQL-скрипт для создания структуры таблиц.

#### `app/views`
Содержит классы виджетов и диалоговых окон.
- **`main_window.py`**: Класс `MainWindow`, который собирает все компоненты в единый интерфейс. Инициализирует контроллеры и управляет основными действиями (показ диалогов, переключение панелей).
- **`dialogs.py`**: Содержит классы для диалоговых окон `SectionDialog`, `CategoryDialog`, `SettingsDialog` и `NoteDialog`.
- **`link_dialog.py`**: Содержит сложный диалог `LinkDialog` для создания и редактирования ссылок, который был вынесен из `dialogs.py`.
- **`category_tiles.py`**: Виджет для отображения категорий в виде плиток.

#### `app/controllers`
Связывает модели и представления, обрабатывая логику взаимодействия с пользователем.
- **`structure.py`**: `StructureController` управляет деревом `QTreeWidget`. Обрабатывает клики, двойные клики и контекстное меню для навигации, добавления и редактирования сфер, разделов и категорий. Сигнализирует `MainWindow` о необходимости обновить контент.
- **`links.py`**: `LinksController` управляет таблицей ссылок `QTableWidget`. Обрабатывает контекстное меню (CRUD, cut/copy/paste, избранное), запуск ссылок и отображение заметок.
- **`ui.py`**: Содержит вспомогательные UI-компоненты: `FavoritesWidget` (панель избранного) и `ThemeController` (управление темами).

#### `app/utils`
Содержит вспомогательные утилиты.
- **`chrome_profiles.py`**: Утилиты для обнаружения и парсинга профилей Google Chrome.
- **`icon_extract.py`**: Модуль для извлечения иконок из исполняемых файлов (`.exe`) и библиотек (`.dll`) для их отображения в интерфейсе.
- **`link_parser.py`**: Логика для обработки и парсинга различных типов ссылок (файлы, URL, команды).

## 4. Техническая архитектура и потоки данных

Приложение построено на гибридном подходе, сочетающем черты MVC и прямого взаимодействия между компонентами для упрощения.

- **Центральный компонент**: `MainWindow` создает все основные виджеты и контроллеры. Он выступает в роли координатора, но делегирует обработку событий специализированным контроллерам.
- **Контроллеры**: `StructureController` и `LinksController` получают в конструкторе экземпляры виджетов (`QTreeWidget`, `QTableWidget`) и базы данных (`Database`). Они напрямую подключают свои слоты к сигналам виджетов (например, `itemDoubleClicked`, `customContextMenuRequested`).
- **Диалоги**: Диалоговые окна (`LinkDialog`, `SectionDialog` и др.) являются самодостаточными. Они получают экземпляр `Database` и напрямую вызывают его методы для сохранения данных (`db.upsert_link()`, `db.upsert_section()` и т.д.) по нажатию кнопки "ОК"/"Сохранить".

### Поток 1: Запуск приложения

1.  `main.py` запускает приложение.
2.  Создается `QApplication`.
3.  `Database()`: Проверяется наличие БД. Если ее нет, создается из `schema.sql` и заполняется начальными данными.
4.  `AppSettings()`: Загружаются настройки из `settings.json`.
5.  `ThemeController()`: Применяется сохраненная тема.
6.  `MainWindow()`: 
    - Инициализируется UI: создаются все панели, меню, виджеты (`QTreeWidget`, `QTableWidget`, `QStackedLayout` и др.).
    - Создаются контроллеры: `self.structure = StructureController(self.tree, ...)` и `self.links = LinksController(self.table, ...)`.
    - Сигналы от контроллеров подключаются к слотам `MainWindow` (например, `self.structure.category_selected.connect(self.load_category)`).
    - Загружается первая сфера и ее содержимое.

### Поток 2: Добавление новой ссылки

1.  **Пользователь** вызывает действие (через контекстное меню `LinksController` или кнопку `F1` в `MainWindow`).
2.  `MainWindow.show_link_dialog()` создает экземпляр `LinkDialog`.
3.  **`LinkDialog`**: 
    - Отображает сложный UI с выбором типа ссылки, каскадными `QComboBox` для выбора категории и другими полями.
    - Пользователь вводит данные и нажимает "Сохранить".
4.  **`LinkDialog._on_accept()`**:
    - Собирает данные из полей в словарь `record`.
    - Вызывает `self.db.upsert_link(record)`, напрямую сохраняя данные в БД.
    - Закрывается с кодом `Accepted`.
5.  **`MainWindow`**:
    - Проверяет `if dlg.exec() == QDialog.DialogCode.Accepted:`.
    - Вызывает `self.load_category(self.current_category_id)` для обновления списка ссылок.
    - `load_category` вызывает `self.links.load_links(category_id)`.
    - `LinksController` запрашивает у `db` новый список ссылок и полностью перерисовывает `QTableWidget`.

### Поток 3: Навигация по дереву

1.  **Пользователь** кликает на элемент в `QTreeWidget`.
2.  **`StructureController`** перехватывает сигнал (например, `itemDoubleClicked`).
3.  В слоте контроллера определяется тип элемента (секция или категория) и его `id`.
4.  Контроллер испускает сигнал, например, `self.category_selected.emit(category_id)`.
5.  **`MainWindow`** в своем слоте `load_category(category_id)`:
    - Вызывает `self.links.load_links(category_id)` для обновления таблицы ссылок.
    - Переключает `QStackedLayout` на `self.table` (индекс 1).
    - Обновляет `self.current_category_id`.

## 5. Запуск приложения

Для запуска приложения необходимо выполнить файл `main.py` из корневой директории проекта:

```bash
python -m app.main
```
